1. What Vexa is

Vexa is a small, interpreted programming language with natural-English statements. You write let score be 10. and if score is greater than 5 then { ... }. Its English phrases are precise syntax, not free-form English: spelling, word order, and lowercase keywords matter.

The interpreter reads the whole file, turns text into tokens, parses an abstract syntax tree (AST), and executes that tree. Syntax errors are found before any statement runs. Runtime errors stop execution when reached; earlier effects remain. There is no compilation step. The core language has no third-party dependency; optional tables use pandas, numerical arrays use NumPy, and machine learning uses PyTorch.

Terminal programs, functions, classes, lists, and optional Tkinter desktop widgets work today. Vexa programs can import other Vexa source files (section 22). Vexa has no exception handling or general file-access functions. Section 20 adds explicit allowlisted PyTorch module access and model/tensor serialization. use gui. enables the GUI library; use pandas. enables the CSV/table phrases in section 18; use numpy. enables arrays in section 19; use pytorch. enables machine learning in section 20.

2. Getting started

Installation

Use the Vexa download page to choose a Windows or macOS installer. The installer includes a private Python runtime and an offline copy of this guide. See installation and troubleshooting for platform requirements, VS Code setup, and optional libraries.

Create a UTF-8 text file called hello.vexa:

say "Hello, World!".

From the same folder, run:

vexa hello.vexa

To run from source, use Python 3.10 or newer and run python3 interpreter.py hello.vexa from the directory containing the interpreter, or give the path to interpreter.py. Substitute python or py where appropriate.

It prints Hello, World! followed by a newline. Paths may be absolute or relative to your terminal's current folder; quote paths containing spaces. The .vexa suffix is the convention (the interpreter does not enforce the extension). A successful run exits with status 0; an interpreter/file error exits with status 1. A filename is required: there is no interactive REPL.

To run the automated suite (pandas-specific tests skip if unavailable) from the Vexa folder:

python3 -m unittest discover -v

3. Syntax essentials

Simple statements end with a period. Newlines and indentation make programs readable but do not end statements. Several statements can share a line, and an expression can span lines. Blocks use { and }. if, loops, class, and define end at their closing brace; do not put a period after the brace.

# This is a comment, lasting until the end of the line.
let message be "# inside a string is text".
if true then {
    say message. # A simple statement still needs its period.
}

Empty blocks, empty lists, and empty argument lists are valid. Commas separate parameters, arguments, and list elements; trailing commas are not supported. A standalone block is not a statement.

Names contain ASCII letters, digits, and underscores, and cannot start with a digit. total, total_2, and _count are valid. Names are case-sensitive: score and Score are different. Reserved keywords cannot be names. Built-in function names are ordinary names, so avoid reusing them unless intentional.

Decimal points versus terminating periods

A period immediately after digits belongs to a number only when followed by another digit. Therefore say 3.14. contains the decimal number 3.14 and a separate terminating period. say 3. prints the integer 3; that period ends the statement. Write 3.0 for a floating-point literal.

say 3.14.
say 3.
say 3.0.
say "Version 1.2".

These print 3.14, 3, 3.0, and Version 1.2. Literal .5 is unsupported: write 0.5. Literal 1e3 is unsupported: write 1000 or use to_float("1e3"). A number cannot have several fractional parts or an adjacent identifier suffix. Periods inside strings or comments have no terminating role.

4. Variables and data types

let name be value. creates a binding. set name to value. changes an existing binding. Using set on an unknown name is an error; declaring the same local name twice is also an error. Variables can later hold a different type.

let score be 10.
set score to score + 5.
let greeting be "Hello".
let ready be true.
let result be null.
say score.
set result to greeting.
say result.

The output is 15 and Hello. The initializer/right side is evaluated before its value is stored. Assignment resolves its destination before evaluating the right side, so an unknown destination fails first.

Value kind Examples Notes
Integer 0, 42, -8 Minus is a unary operator, not part of the literal.
Floating-point number 0.5, 12.0 Finite binary floating-point, with rounding limits.
String "Hello", "" Unicode text, double quotes required.
Boolean true, false Distinct from numbers; true is not 1.
Null null Absence of a result.
List [1, "two", null] Ordered, mutable values; may be nested.
Function A defined function or built-in Can be stored, passed, and returned.

Strings support exactly \n (newline), \r (carriage return), \t (tab), \" (quote), and \\ (backslash). Raw newlines inside a string and unknown escapes are errors. There is no interpolation; concatenate with +.

say "First\nSecond".
say "A quote: \" and a backslash: \\".

Integers use Python's integer representation; floats use Python's float precision. Very large integers, deep recursion, and deeply nested expressions remain subject to host limits. Floating-point results such as 0.1 + 0.2 can have rounding artifacts; do not assume exact decimal accounting arithmetic.

5. Operators and precedence

Arithmetic operators are +, -, *, /, %, and ^ (power). / produces a float even for 4 / 2. % is remainder, with the divisor's sign: -7 % 3 is 2. + also joins two strings or two lists. Other arithmetic requires numbers. Booleans do not count as numbers. There is no implicit conversion: use "Score: " + to_string(score), not "Score: " + score.

Comparison Meaning
a is equal to b Equality
a is not equal to b Inequality
a is greater than b Greater
a is less than b Less
a is greater than or equal to b Greater or equal
a is less than or equal to b Less or equal

Equality compares lists structurally, including nested values. Integers and floats can be numerically equal (1 is equal to 1.0), but booleans and numbers are distinct. Different value types compare unequal otherwise. Functions compare by identity. Ordering requires two numbers or two strings; strings compare lexicographically by Unicode code points. Lists cannot be ordered.

Use and, or, and not for logic. All evaluated logical operands and conditions must be booleans, not numbers, strings, lists, or null. and and or short-circuit: they skip their right operand when the left determines the result.

say 2 + 3 * 4.              # 14
say (2 + 3) * 4.            # 20
say 2 ^ 3 ^ 2.              # 512
say -2 ^ 2.                 # -4
say 2 ^ -2.                 # 0.25
say not 3 is equal to 4.     # true
say false and missing.      # false; missing is never looked up
say true or false and false. # true
say 3 is greater than or equal to 3.

Precedence from lowest to highest:

Level Operators
1 or
2 and
3 not
4 English comparison phrases
5 +, - (binary)
6 *, /, %
7 Unary +, -
8 ^
9 Function call (...), list index [...]

Parentheses override precedence. Power groups to the right; other binary arithmetic and logical operators group to the left. Power accepts a unary exponent, which is why 2 ^ -2 works. Comparisons do not chain: write x is greater than 0 and x is less than 10, rather than joining three operands with comparison phrases. Neither == nor != nor symbolic ordering is supported. Division by zero, nonfinite numbers, and complex results are errors.

6. Input and output

say expression. prints a value followed by a newline. Strings print without quotes; booleans and null print lowercase. Lists print with brackets and quoted, escaped string elements. Functions print as <function>.

print expression. uses the same formatting but adds no newline, like Java's System.out.print(). say adds a newline, like System.out.println(). Both accept variables and expressions and require a terminating period.

print "Hello ".
say "World!".
let score be 42.
print "Score: " + to_string(score).

This produces Hello World! on one line, followed by Score: 42 on the next line with no newline after 42. Use say when output should end a line.

ask prompt into name. prints a string prompt without a newline, flushes it, and reads one line as a string, removing the line ending. An empty line is valid. End of input is an error. It updates the nearest existing binding, or creates one in the current scope if absent.

# test-input: ["Alex", "20"]
ask "Name? " into name.
ask "Age? " into age_text.
let age be to_int(age_text).
say "Hello, " + name + ". Next year: " + to_string(age + 1).

Enter Alex and 20 when prompted. The final line says Hello, Alex. Next year: 21. The test-input comment supplies automated test input; it has no special meaning to Vexa.

to_int and to_float parse strings only. They trim surrounding whitespace. to_int("12") returns an integer; it does not truncate "12.5". to_float("12.5") returns a float and also accepts exponent strings like "1e2". to_string(value) returns the same representation used by say and print. There is no boolean-conversion built-in. Invalid input stops the program; Vexa currently has no try/catch or built-in validation predicate for numeric text.

7. Conditionals

An if requires then and a boolean condition. The first matching branch runs. An optional else if checks another condition; else runs when none matched.

let age be 18.
if age is greater than 18 then {
    say "Over 18".
} else if age is equal to 18 then {
    say "Exactly 18".
} else {
    say "Under 18".
}
if age is greater than or equal to 18 then {
    if age is less than 65 then { say "Working-age adult". }
}

This prints Exactly 18 and Working-age adult. Conditions can contain comparisons combined with and, or, and not. Untaken branches are not executed, though their syntax is still checked.

8. Loops

While

while condition { ... } checks its boolean condition before each iteration. Update the variables that control it so it can finish.

let n be 1.
while n is less than or equal to 3 {
    say n.
    set n to n + 1.
}

This prints 1, 2, 3. A false initial condition means zero iterations.

Repeat

repeat count times { ... } evaluates its count once. The count must be a nonnegative integer; 3.0 and true are invalid counts. Zero does nothing. There is no implicit loop counter; create one if needed.

let count be 0.
repeat 3 times {
    set count to count + 1.
    say count.
}

Counter-Based For Loops

for name from start to end step amount { ... } creates a local tracking variable and advances it automatically. The start is inclusive and the end is exclusive. Omit step amount to use a step of 1.

for i from 0 to 10 { say i. }          # 0 through 9
for i from 0 to 10 step 2 { say i. }   # 0, 2, 4, 6, 8
for i from 10 to 0 step -2 { say i. }  # 10, 8, 6, 4, 2

Start, end, and step expressions are evaluated once, in that order, before creating the tracking variable. Each must evaluate to an integer; booleans and floats such as 1.0 are rejected. A zero step raises a runtime error, including when the bounds would otherwise produce no iterations. Equal bounds or a step pointing away from the end produce no iterations.

Nested loops create independent bindings, and outer bindings keep their values:

let i be 99.
for i from 0 to 2 {
    for j from 0 to 3 {
        say i * 3 + j.
    }
}
say i. # 99; j is unavailable here

continue. advances the counter before the next iteration, and break. exits the nearest loop. Assigning to the tracking variable changes its visible value for the rest of that iteration; the next iteration still follows the original automatic progression. The body shares the loop's local scope across iterations. Other existing outer variables can be updated with set; bindings created in the loop are unavailable afterward. See the launch guide for editor support and more examples.

For each

for each name in list { ... } visits a shallow snapshot of a list. Strings are not iterable in this construct. The list expression is evaluated once.

let values be [10, 20, 30].
for each value in values {
    say value.
    append(values, 99).
}
say length(values).
say value.

This prints 10, 20, 30, 6, and 30. Appending does not add iterations. The iteration binding is in the current scope and remains afterward. It updates an existing local binding or shadows an outer one. An empty list creates no binding and leaves existing bindings unchanged. The snapshot copies only the outer list; mutations to nested shared lists remain visible.

Break and continue

break. leaves the innermost loop. continue. skips to its next iteration (and a while loop checks its condition again). Neither is allowed outside a loop, even in an unreachable branch. A function cannot break its caller's loop.

let n be 0.
while true {
    set n to n + 1.
    if n is equal to 2 then { continue. }
    if n is equal to 4 then { break. }
    say n.
}

The output is 1, 3. Beware that braces do not create local scopes: a let inside a loop would attempt to declare the same name again on the next iteration. Declare accumulators before the loop and update them with set.

9. Functions and scope

Optionally declare a return type after the parameters:

define square with (x) -> int {
    return x * x.
}
say square(5).

Supported return types are int, float, string, bool, null, list, and tensor. tensor accepts genuine PyTorch tensors (including parameters) after use pytorch.. Matching is exact: bool is distinct from int, and an int does not match float. List annotations check the list itself, not its elements. Every executed return is checked; finishing without a return produces null, which must also match the annotation. Mismatches report a runtime error with a source location; unknown annotation names are syntax errors. Annotations are optional and do not change function calls or lexical scope.

Define a function with define name with (parameters) { ... }. Call it with name(arguments). Arguments use commas, and the argument count must exactly match the parameter count. Duplicate parameter names are invalid.

define add with (a, b) {
    return a + b.
}
say add(3, 4).
define greet with () { say "Hello". }
greet().
say greet().

This prints 7, Hello, Hello, and null. A call can be an expression or a statement whose result is discarded. return expression. immediately leaves the current function, including nested loops. return null. is an explicit empty result; bare return. is unsupported. Falling off the body returns null. return is invalid outside functions, including unreachable branches.

Recursion

A function can call itself after its definition has executed. Include a base case that stops the recursion.

define factorial with (n) {
    if n is less than or equal to 1 then { return 1. }
    return n * factorial(n - 1).
}
say factorial(5).

This prints 120. Recursive calls get separate parameter and local bindings. Deep recursion hits a host limit; Vexa does not optimize tail calls.

Lexical scope and closures

The program has a scope. Each function call has a new child scope of the scope where the function was defined, not where it was called. Blocks share their enclosing scope. let and define reject a duplicate in the current scope but can shadow an outer name. set changes the nearest existing name. Parameters are local bindings, so redeclaring a parameter with let fails.

let x be 10.
define read with () { return x. }
define caller with (x) { return read(). }
say caller(99).
if true then { let visible be "blocks share scope". }
say visible.
define make_counter with (start) {
    define next with () {
        set start to start + 1.
        return start.
    }
    return next.
}
let counter be make_counter(0).
say counter().
say counter().

This prints 10, blocks share scope, 1, 2. The returned function retains its defining environment (a closure). Changes to captured bindings remain visible; environments are not frozen copies. Functions and built-ins are values, so they can also be passed as arguments or stored in lists. Calls evaluate the callee first, then arguments from left to right.

Definitions execute in order: calling a function before its define runs is an undefined-name error. A function may refer to another function defined later, provided that other definition has executed by the time the reference is used. Built-ins occupy a parent of program scope and can be shadowed with let.

10. Lists

List literals use brackets and may mix types or contain other lists. Indices start at zero and must be nonnegative, in-range integers: neither true nor 0.0 is a valid index. Only lists support indexing; strings do not.

let fruits be ["apple", "banana"].
say fruits[0].
set fruits[1] to "mango".
append(fruits, "pear").
for each fruit in fruits { say fruit. }
say pop(fruits).
say length(fruits).
let rows be [[1, 2], [3, 4]].
set rows[0][1] to 9.
say rows.

set replaces an existing element; it does not grow the list. append adds at the end; pop removes and returns the last element. Popping an empty list fails. There are no slices, negative indices, or list methods such as fruits.append.

Assignment and function arguments share list references. Concatenation creates a new outer list, but nested elements are still shared (a shallow copy).

let original be [[1]].
let alias be original.
let joined be original + [2].
set alias[0][0] to 9.
say original.
say joined.

This prints [[9]] and [[9], 2]. To modify a list in a function, pass it as an argument and call append, pop, or indexed set. Rebinding a parameter with set changes that parameter, not the caller's variable.

Indexed assignment resolves its list and index before evaluating the right side. If that evaluation changes list length, bounds are checked again before storing. Cyclic lists are permitted: display uses a [...] recursion marker, and equality handles cycles. Deep acyclic nesting still has a host depth limit.

12. Errors and debugging

Command-line diagnostics look like myprogram.vexa:2:7: Division by zero: filename, one-based line, one-based column, and explanation. Parser errors also identify the unexpected token or end of input. Runtime locations point to the relevant statement/operator/call, and deep-runtime-limit errors may point to the containing top-level statement. There is currently no Vexa stack trace.

Error or symptom Likely cause and repair
Expected '.' after statement Add a period after a simple statement; inspect the preceding line too.
Expected '}' to close block Match each opening brace with a closing one.
Unexpected period after } Remove it from a compound statement.
Unterminated string Close double quotes; use \n for embedded newlines.
Invalid string escape Use only the five documented escapes.
Invalid numeric literal Use 0.5, no exponent literal, no adjacent identifier suffix.
Undefined name Check spelling/case and define the name before using or setting it.
Duplicate binding Use set to update; move let outside a repeating loop.
Logical operands must be booleans Write a comparison instead of using a number as a condition.
Arithmetic requires numbers Convert text explicitly; concatenate two strings, not text and a number.
Division by zero Check the divisor before / or %; zero to a negative power also fails.
Invalid numeric input Enter valid decimal text; conversions accept strings only.
List index out of range Check 0 <= index < length using English comparisons joined by and.
Incorrect argument count Match the function's parameters exactly.
Invalid break, continue, return Put them in the appropriate loop/function; unreachable code is still parsed.
Recursion/nesting limit Reduce nesting or use an iterative algorithm and a terminating base case.
End of input while reading ask Supply all requested lines through the terminal or redirected input.

Start with the first diagnostic. Add say statements before the failing step to inspect values; run a smaller program to isolate the problem. Syntax errors prevent all execution, while runtime failures can follow earlier output/mutations. There is no automatic rollback. Use a comparison to guard a risky operation:

let divisor be 0.
if divisor is not equal to 0 then {
    say 10 / divisor.
} else {
    say "Cannot divide by zero".
}

Memory exhaustion, infinite loops, and extreme host resource use are not sandboxed or automatically timed out. Normal syntax/type/numeric errors receive Vexa diagnostics; resource limits do not make arbitrarily large programs executable.

13. Complete practical programs

Save each block in the named .vexa file and run it with python3 interpreter.py filename.vexa. Matching files are in examples/. Test-input comments show sample input lines; type them when prompted.

Terminal calculator — calculator.vexa

This performs one calculation per run. Input is converted to floats; the selected operator determines the branch. Division is guarded. Invalid numeric text raises a conversion error; this is a terminal calculator, with no GUI.

# test-input: ["8", "/", "2"]
ask "First number? " into first_text.
ask "Operator (+, -, *, /)? " into operator.
ask "Second number? " into second_text.
let a be to_float(first_text).
let b be to_float(second_text).
if operator is equal to "+" then { say a + b. }
else if operator is equal to "-" then { say a - b. }
else if operator is equal to "*" then { say a * b. }
else if operator is equal to "/" then {
    if b is equal to 0 then { say "Cannot divide by zero". }
    else { say a / b. }
} else { say "Unknown operator". }

Sample inputs 8, /, 2 produce 4.0 after the prompts.

Even/odd checker — even_odd.vexa

An integer is even when its remainder after division by two is zero. This also works for negative integers.

# test-input: ["7"]
ask "Integer? " into text.
let number be to_int(text).
if number % 2 is equal to 0 then { say "Even". }
else { say "Odd". }

Input 7 produces Odd after the prompt.

Multiplication table — multiplication_table.vexa

A counter supplies the multiplier. Initialize it outside the loop, then update it each time so the loop ends after ten rows.

# test-input: ["3"]
ask "Table for? " into text.
let number be to_int(text).
let factor be 1.
while factor is less than or equal to 10 {
    say to_string(number) + " x " + to_string(factor) + " = " + to_string(number * factor).
    set factor to factor + 1.
}

For 3, rows run from 3 x 1 = 3 through 3 x 10 = 30.

Random number generator — random_number.vexa

Both bounds are inclusive. Checking their order lets the program explain the mistake before calling the built-in. Equal bounds always return that bound.

# test-input: ["1", "6"]
ask "Minimum? " into low_text.
ask "Maximum? " into high_text.
let low be to_int(low_text).
let high be to_int(high_text).
if low is less than or equal to high then {
    say random(low, high).
} else { say "Minimum must not exceed maximum". }

Inputs 1, 6 print an integer from 1 through 6 after the prompts.

List summary — list_summary.vexa

A function receives a list and computes a total with a local accumulator. The caller uses the returned value to calculate the average.

define total with (values) {
    let sum be 0.
    for each value in values { set sum to sum + value. }
    return sum.
}
let scores be [12, 18, 24].
append(scores, 30).
say "Total: " + to_string(total(scores)).
if length(scores) is greater than 0 then {
    say "Average: " + to_string(total(scores) / length(scores)).
}

This prints Total: 84 and Average: 21.0. The empty-list guard avoids division by zero. The function's sum does not leak into program scope.

Predictions, loss, backpropagation and optimizers

A prediction is the model output. A loss measures how far predictions are from targets. An optimizer adjusts trainable parameters. Backpropagation computes how each parameter affects the loss; PyTorch's autograd does this work. Vexa never substitutes a separate gradient engine.

This tiny runnable training exercise learns a numeric relationship, without a complete dataset project:

# ml-example
use pytorch.
let inputs be tensor with [[1.0], [2.0], [3.0]].
let targets be multiply inputs by 2.
let model be linear layer with (1, 1).
let criterion be mean squared error loss.
let optimizer be adam optimizer for model with learning rate 0.01.
let predictions be null.
let loss be null.
training mode for model.
repeat 10 times {
    clear gradients of optimizer.
    set predictions to predict with model using inputs.
    set loss to calculate loss using criterion with (predictions, targets).
    calculate gradients from loss.
    update weights using optimizer.
}
say scalar value of loss.
evaluation mode for model.
say infer with model using inputs.

Inputs are three examples with one feature each. Targets are twice each input. The model starts with random weights. The criterion creates real MSELoss, which requires identical prediction and target shapes here, avoiding accidental broadcasting. The optimizer takes the model's parameters. let declares each binding once; set updates it inside the loop, preserving Vexa's scope rules. Each iteration clears old gradients, runs a forward pass, measures loss, computes gradients with .backward(), then changes parameters with .step(). Ten iterations demonstrate the mechanism; they do not guarantee an accurate model.

sgd optimizer for model with learning rate 0.01 constructs SGD instead. Both optimizer forms accept extra keywords, for example sgd optimizer for model with learning rate 0.01 with options (momentum as 0.9). parameters of model returns a list of genuine parameter objects. training mode for model. calls .train() and evaluation mode for model. calls .eval(), controlling dropout/batch normalization behavior.

predict with model using inputs preserves gradients in either mode. infer with model using inputs uses torch.no_grad() for that call only; it does not change model mode. Set evaluation mode explicitly for inference. Do not use infer for the training forward pass. Extracting scalar/list values also breaks gradient tracking for those extracted values.

For classification, cross entropy loss creates CrossEntropyLoss. Use calculate loss using criterion with (predictions, targets) with raw class scores (logits). Integer class targets use int64, usually shape [batch], while scores have shape [batch, classes]. PyTorch also accepts floating probability targets of the same shape as scores. Shape/type failures show source locations and useful underlying details. Dtype mismatch in a linear layer can also cause failure: convert inputs to "float32" when the model uses its default dtype.

English phrases cover common tasks; they do not promise full PyTorch support. The shared PythonBridge now exposes explicit module/member/call expressions:

Custom nn.Module classes

nn.Module is an explicit allowlisted reference in a class's parent position, activated by use pytorch.. It does not import arbitrary Python classes or create an unrestricted nn namespace. Other Python bases are rejected.

# ml-example
use pytorch.
class NeuralNetwork(nn.Module) {
    define __init__ with () -> null {
        super().__init__().
        set self.linear to linear layer with (2, 1).
    }

    define forward with (x) -> tensor {
        return self.linear(x).
    }
}
let model be NeuralNetwork().
let inputs be tensor with [[1.0, 2.0]].
let output be predict with model using inputs.
say output.

Construction returns a real Python torch.nn.Module. Call super().__init__() exactly once before assigning attributes in a custom constructor. A class without a constructor inherits its Vexa parent's constructor, or initializes nn.Module automatically when there is no Vexa constructor. Further Vexa subclasses and nested custom models are supported. super() follows Vexa method inheritance; the only exposed Python parent method is nn.Module.__init__.

set self.layer to ... uses PyTorch attribute assignment, preserving submodule and Parameter registration, autograd, device moves and recursive train/eval modes. Plain tensors remain ordinary attributes, as in PyTorch; use nn.Parameter via the explicit member/call bridge for trainable standalone tensors. Public attributes you assign, Vexa methods, and read-only training are accessible; private/internal attributes, arbitrary Python methods and overwriting PyTorch methods are rejected. Call self.layer(x) or use predict with self.layer using x. -> tensor validates real tensor results without detaching the graph. Shape/device and callback errors become located Vexa runtime diagnostics, including calls initiated from Python.

The existing optimizer, parameters, inference, move, training/evaluation and save/load weights phrases work on custom models. Save state dictionaries with save model weights of model to "weights.pth". and load into a newly constructed matching architecture with load model weights into model from "weights.pth".. Whole-model pickle, TorchScript/compile, concurrent Python callback execution and arbitrary Python method overrides are outside this bridge's supported API. The PyTorch Module contract describes parent initialization, attribute registration and state dictionaries.

There are no decorators, context managers, Python callbacks from Vexa functions, tuple/dictionary literals, keyword splats, device-wide automatic transfers, mixed precision training helpers, or distributed training syntax. Python callables can pass through the bridge; Vexa functions cannot act as Python callbacks. No pretrained weights or datasets are fetched automatically by the English defaults. Advanced model factories may download if explicitly called with download-triggering options. Desktop editor behavior and actual CUDA execution remain unverified in this environment.

21. Classes and objects

Declare a class with methods using the existing define syntax, then call the class to create an instance:

class Person {
    define __init__ with (name) -> null {
        set self.name to name.
    }
    define greet with () {
        say "Hello".
    }
    define rename with (name) {
        set self.name to name.
    }
}
let p be Person("Alex").
let q be Person("Sam").
p.greet().
p.rename("Ada").
q.rename("Grace").
say p.name. # Ada
say q.name. # Grace

Save this example as people.vexa and launch it with python3 interpreter.py people.vexa (or vexa people.vexa with the local launcher).

Each instance owns independent properties. set object.property to value. creates or replaces a property; reading an unset property raises an error. Property names must immediately follow the dot (p.name). Reads, calls, and indexing can chain, as in p.friend.greet() or p.items[0]. A property shadows a method of the same name.

Methods automatically receive self in their local call scope: omit it from the parameter list. Declaring a parameter named self in a method is an error. Methods otherwise follow ordinary function rules, including return annotations, argument counts, lexical scope, and closures. A saved method (let greet be p.greet.) keeps its instance when later called as greet(). self is an ordinary local binding and is undefined outside methods unless explicitly bound in the enclosing scope.

Class declarations bind names when executed, follow existing duplicate binding and shadowing rules, and accept only method definitions. Duplicate method names are errors, including in unused classes. Empty classes are allowed.

Single inheritance

Use Python-style parentheses to name one parent:

class Animal {
    define __init__ with (name) { set self.name to name. }
    define speak with () -> string { return "Unknown". }
    define describe with () { return self.name + ": " + self.speak(). }
}
class Dog(Animal) {
    define speak with () -> string { return "Woof". }
}
let dog be Dog("Rex").
say dog.speak(). # Woof
say dog.describe(). # Rex: Woof

The parent name resolves in the current lexical scope when the declaration runs; it must already refer to a Vexa class, or be the explicit nn.Module base from section 20. Forward references, invalid parent types, and inheritance cycles are rejected. Only one parent is allowed. Methods are searched from child to parent, so child definitions override inherited methods. Inherited methods (including saved bound methods) receive the actual child instance as self, and calls through self use child overrides. A child without __init__ inherits its nearest ancestor's constructor, including its arguments and property initialization. Each instance has independent properties. A child defining __init__ replaces the inherited constructor; parent constructors do not run automatically in that case. Call super().__init__(arguments) to initialize the same instance through a parent constructor:

class Person {
    define __init__ with (name) { set self.name to name. }
}
class Student(Person) {
    define __init__ with (name, grade) {
        super().__init__(name).
        set self.grade to grade.
    }
}
let s be Student("Alex", 9).
say s.name.
say s.grade.

Inside an instance method, super().method(arguments) searches for a method starting at the parent of the class that defined the current method. This stays correct across multiple inheritance levels and inherited or saved bound methods. The parent method receives the same instance as self; calls through self still use child overrides. Parent method lookup ignores instance properties. super() takes no arguments and is reserved syntax. It is invalid at top level, in ordinary functions, and in nested helper functions, even when called by a method. Missing parent methods (including __init__) raise runtime errors; a root class has no parent methods. Parent calls use normal argument counts, return annotations, and constructor return checks.

The constructor method __init__ runs automatically on the newly created instance. Class call arguments are passed to it, and self is bound automatically. Its parameter count must match the arguments exactly. Constructors can initialize properties with set self.name to name. and must return null, either explicitly (return null.) or implicitly by reaching the end. Returning any non-null value raises a runtime error, including when calling instance.__init__() directly. The -> null annotation is optional. Any other constructor annotation is a parse error, even if the class is never instantiated. Classes with no __init__ anywhere in their ancestry accept zero arguments only.

Return types on methods

Save this as calculator.vexa and run python3 interpreter.py calculator.vexa:

class Calculator {
    define add with (a, b) -> int { return a + b. }
    define positive with (n) -> bool { return n is greater than 0. }
    define reset with () -> null {}
    define echo with (value) { return value. }
}
class ExtendedCalculator(Calculator) {
    define add with (a, b) -> int { return super().add(a, b). }
}
let calc be ExtendedCalculator().
say calc.add(4, 5).
say calc.positive(10).

This prints 9 and true. Inherited methods, overrides, saved bound methods, and super() calls check the annotation of the method actually executed. Overrides may choose their own annotation or omit it. Unannotated methods accept any return value. Checks use exact runtime types: true cannot satisfy int, and 1 cannot satisfy float. Falling off the body produces null and must satisfy the annotation too. For example, returning "nine" from add raises a return type mismatch naming Calculator.add at the return statement; a missing return points to the method declaration.

22. Modules and Imports

A Vexa module is a UTF-8 .vexa source file. Use from … import … to bind selected names in the current scope, or import … to bind the module namespace. Both forms end with a period. Module paths use dots for folders and omit the .vexa suffix.

Import a function from a sibling file

Save the following as hello.vexa:

let greeting be "Hello".
let punctuation be "!".

define printHello with () {
    say greeting + punctuation.
}

class Greeter {
    define __init__ with (name) {
        set self.name to name.
    }

    define greet with () {
        say greeting + ", " + self.name + punctuation.
    }
}

Save this as main.vexa in the same folder:

from hello import printHello.
printHello().

Run vexa main.vexa from that folder, or run python3 /path/to/interpreter.py main.vexa using your interpreter's actual path. The program prints Hello!.

Import a module namespace

Keep the same hello.vexa and replace main.vexa with:

import hello.
hello.printHello().
say hello.greeting.
let greeter be hello.Greeter("Ada").
greeter.greet().

This prints Hello!, Hello, and Hello, Ada! on separate lines. hello is the local name for the module namespace. Use hello.member to read a variable, call a function, or get a class. Create an object by calling the class with its constructor arguments, as in hello.Greeter("Ada").

Multiple imports, aliases, and subdirectories

Keep hello.vexa beside main.vexa and copy the same hello.vexa into a tools subfolder. The layout is:

main.vexa
hello.vexa
tools/
    hello.vexa

Replace main.vexa with:

greet().
helpers.printHello().

greeter.greet().

This prints Hello! twice, then Hello, Lin! and Hello!. Commas separate modules in an import statement and names from the same module in a from statement. Use another from statement to select names from a different module. Put as alias after the module or name you want to rename. A dotted module path such as tools.hello defaults to the final name, hello, so the alias helpers avoids a duplicate binding in this example.

Resolution, caching, and shared values

  • Paths are relative to the file containing the import. For example, an import sibling. inside tools/hello.vexa searches for tools/sibling.vexa, even if it appears inside a function called from main.vexa. The terminal's working directory only affects how a relative entry filename is found.
  • The interpreter parses and executes a module when the first import reaches it. Top-level statements run in an isolated module scope with access to Vexa built-ins. The interpreter caches a successfully executed module by its resolved file path for the current run. Multiple aliases of the same file share one namespace. Different files with the same name load separately.
  • A module exposes the bindings created in its module scope, including imported names. Its functions and class methods keep access to that scope after import. Namespace reads see the current module binding. A named import binds the current value locally. If a module later reassigns its variable, the existing named import keeps its original value. Mutable values such as lists are shared, so changes to their contents can be visible through either binding.
  • Namespace bindings are read-only from outside the module. Use a function defined in the module to update its variables. Use a named class import if you want to use an imported class as a Vexa parent class, for example import Greeter and then declare class Friendly(Greeter) {}.

Circular imports and common errors

A circular import occurs when an import reaches a file that is already being executed as part of the current load chain. For example, if main.vexa imports hello.vexa and hello.vexa imports main.vexa at the top level, the interpreter reports Circular import with the file chain. Move shared definitions into a third module that both files can import.
